# Contributing to SnowNinja

First off, thanks for taking the time to contribute! 🎉

The following is a set of guidelines for contributing to SnowNinja. These are mostly guidelines, not rules. Use your best judgment, and feel free to propose changes to this document in a pull request.

## How Can I Contribute?

### Reporting Bugs
- **Check the Issues**: Before opening a new issue, please check if the bug has already been reported.
- **Provide Detail**: Include your OS, Python version, and the exact steps to reproduce the issue.
- **Screenshots**: If it's a TUI/UI bug, a screenshot or recording is extremely helpful.

### Suggesting Enhancements
- **Draft a Plan**: Use `/plan` in the SnowNinja CLI to draft your enhancement idea.
- **Open an Issue**: Describe the feature, why it's needed, and how it should work.

### Pull Requests
- **Branch naming**: Use descriptive branch names (e.g., `feat/new-tool`, `fix/login-bug`).
- **Tests**: Ensure all tests pass (`pytest`) before submitting.
- **Docs**: Update `docs/ARCHITECTURE.md` or `docs/COMMANDS.md` if you are changing core behavior.

## Style Guide
- We follow [PEP 8](https://www.python.org/dev/peps/pep-0008/) for Python code.
- Use `ruff` for linting and formatting.
